============================================================
  微信群自动客服机器人 —— 使用说明
============================================================

【这是什么】
  一个在微信群里自动看消息、回答客户咨询的小程序。它只接跟我们业务
  相关的咨询（羽绒服相关的款式、尺码、发货、售后等），群里闲聊它不插话；
  涉及退款、投诉、查订单这类要真人的，它不回，只记在日志里等人处理。


【用之前要做四件事】

  1) 装 Python **3.11**（3.10 / 3.12 也行；**别装 3.13 及以上**）
     下载：https://www.python.org/downloads/
     页面上最大的那个按钮给的是最新版（3.13/3.14/3.15），**不要点它**——
     往页面上找 "Looking for a specific release?"，选 **Python 3.11.x**，
     然后点 "Windows installer (64-bit)"。
     为什么：机器人要用的 OCR 引擎（rapidocr-onnxruntime）只支持到 3.12，
     在新版 Python 上根本没有现成的安装包，装依赖会报
     "No matching distribution found"，看着像网络问题，其实是 Python 版本太新。

     安装时**必须勾上最下面那个 "Add python.exe to PATH"**，不勾后面会报错。

  2) 把微信登录好，窗口开着
     （不用管它，机器人自己会切群、读消息、发回复）

  3) 打开 groups.txt，用记事本写好要盯的群名，一行一个
     群名必须和微信里显示的**一模一样**，差一个字就找不到那个群。
     这里面列出的群，机器人都会自动回复。

  4) 把要盯的群在微信里**置顶**（在群里右键 → 置顶该聊天），并把微信窗口**最大化**
     这两步**别省、也别改小窗口**：
     * 窗口小于约 1000x700 时，微信会把会话列表压成一条窄栏，机器人认不出群，
       启动时会直接提醒。每次启动前看一眼微信是不是最大化（标题栏双击即可）。
     * 群一多，会话列表挤不下、被新消息顶到下面去，机器人找不到那个群时只能
       退回"在搜索框里打字找群"——慢一拍，而且每次都抢一下窗口。置顶之后
       它们永远在最上面，一眼就能看到。


【怎么启动】

  第一次：双击  dryrun.bat     ← 只判断该怎么回、**不真的发送**
          看几分钟，确认它在该回的时候回、该闭嘴的时候闭嘴。

  正式跑：双击  start.bat
          * 第一次启动会自动装依赖，要等几分钟；装好以后就直接跑。
          * 弹出的黑窗口就是它，别关。停止按 Ctrl+C，或直接关窗口。
          * 同目录的 bot.log 是完整记录。出问题把这个文件发给对方。


【平时怎么用】

  * 加群 / 换群：改 groups.txt，重新启动。
  * 机器人会自己切群读消息，切的那两三秒会抢一下前台窗口，之后自己切回来。
    你正好在打字时偶尔会被切走，切回来继续即可。


【出问题了怎么办】

  先看两个地方：

  1) 黑窗口里的输出（同目录的 bot.log 里有同样一份）。
     每批消息都会打一句判定，例如：
         → 判定 reply：命中快递问答        （该回，接着能看到发送结果）
         → 判定 ignore：群友闲聊无关业务   （正确地不回）
         [OK] 已发送 [某某群]: ...
     如果连"判定"都没打，说明它**根本没读到消息**，看下面第 2 条。

  2) 双击  diagnose.bat   ← 一键体检
     它生成一个报告和五张图（和脚本同目录）：
         diagnose-report.txt      环境 / 微信窗口 / 截图质量 / 布局测量 /
                                  会话列表读到的原文 / 群名逐个比对 / Dify 检索
         diagnose-screenshot.png  **机器人干活用的那张图**（最关键的一个文件）
         diagnose-shot-1~4-*.png  **四种截图取法各自拿到的画面**
                                  （哪张能看见微信，哪条路就是这台机器上能用的那条）
     把 report 和这几张图一起发回给开发者，多半一眼就能定位。
     （跑之前先把机器人停掉：两边会抢前台窗口。）

  几个"看着像坏了、其实没坏"：
     * 群里闲聊它不接话 —— 设计如此。
     * 涉及退款/查订单它不回 —— 只记日志等人工。
     * 同一个问题 30 秒内问第二遍，它不重复回。
     * 发完等 10~20 秒才回 —— 扫列表 + 切群 + 调模型都要时间。

  真正要修的那种：
     * 启动时黑窗口里那一行「[截图] 取法=…」——先看它：
       「可以干活」＝机器人看得见画面；「**拿不到画面**」＝它等于瞎的，什么都不回。
       同一行后面会列出四种取法各自的情况，哪种空白、哪种被挡住，一眼能看出来。
     * 日志/诊断说「四种截图办法都只拿到空白图」→ 机器人等于瞎的，什么都不会回。
       按可能性排：① 这台机器是**远程桌面**，而远程窗口被最小化或已断开
       （断开后 Windows 就停止渲染桌面，所有截图都会变空白 —— 云主机上十有八九是这个）；
       ② 微信最小化了；③ 微信被别的窗口完全盖住。
       保持远程桌面窗口开着（别最小化、别断开），微信恢复出来，再跑一次诊断。
     * 诊断说「机器人用的取法: 屏幕抓取」→ 这台机器上只有"直接抓屏幕"这一条路能拿到
       画面。那么**微信窗口必须一直露在最前面**（别让浏览器、文件夹挡住它）：
       一旦被挡住，机器人读到的就是压在它上面的那个窗口 —— 比读不到更容易出错。
     * 诊断说「有窗口压在微信上面」→ 同上，先把微信窗口露出来或最大化，再跑诊断。
     * 诊断说「这个黑窗口是以管理员身份跑的」→ 不是说这样一定会坏，而是**反过来才一定会坏**：
       微信提权、黑窗口没提权时，系统会把按键和粘贴全丢掉（机器人能读能判，就是发不出去）。
       最省事的做法是**两个都别用管理员**：关掉黑窗口，直接双击 start.bat 重来。
       报告第 3 节会把两边的权限级别都打出来，对一下就知道。
     * 日志里一直刷「点到的不是 [某群]（标题=…）」然后「切不过去，本轮跳过」→
       说明**聊天标题没读全**（标题那一带被裁掉了几个字，机器人认不出当前是哪个群，
       于是每次都判自己点错了）。跑一次诊断，看第 8 节读出来的标题、以及同目录的
       diagnose-crop-title.png（那就是机器人喂给识别的**标题那一条**，一眼能看出有没有切字）。
       最快的自救办法：**把微信窗口最大化**再重启机器人（窗口太窄时各栏挤在一起，
       边界容易量歪）。
     * 日志里一直刷「不在会话列表可视区」→ 群名对不上，或群被挤到列表下面了。
       先把要盯的群**置顶**，再看 诊断报告.txt 第 7 节（它会列出列表里实际读到的字）。
     * 日志里刷「微信窗口是最小化的」→ 点任务栏把微信恢复出来，机器人会自动继续。


【三条不要做】

  * 不要用"以管理员身份运行"打开微信。
    微信一旦提权，普通权限的 python 发给它的按键和粘贴会被系统整段丢掉，
    机器人看起来"完全没反应"（这是最容易踩的坑）。要让两边权限一致，
    最省事的方向是**都不提权**，而不是把机器人也提上去。
  * 不要把微信最小化。最小化时截到的是**过时的旧画面**，机器人会主动停工等你恢复
    （它不会乱回，但也不干活），日志里会提醒你。
  * 不要改 .py 文件。要调的东西都在 groups.txt 和 config.json 里。


【它不会做什么】

  * 不会在群里闲聊时插话。
  * 不会编答案：知识库里没有的就说"转人工"，不会硬答。
  * 不会发链接、电话、二维码。
  * 不会回自己的消息（不会自己跟自己聊）。
