# 文心飞桨星河社区插件 —— 修复版（0.1.2）

## 这是什么

`ernie-paddle-aistudio-api`（Dify 里显示为 **「文心飞桨星河社区」**）这个插件的修复版。

原包出处：Dify Marketplace 收录的 `LiaoYFBH/ernie-paddle-aistudio-api`，版本 **0.1.1**（作者 paddle-aistudio）。
marketplace 上只有这一个包，没有更新版本可用 —— 下面两个 bug 官方一直没修。

修的是**插件自己的代码**，没有动你的任何配置、也没有动 Dify 本体。

## 原包的两个 bug

### 1. `get_num_tokens` 返回类型违反插件协议（就是你看到的报错）

`models/text_embedding/embedding.py` 原代码：

```python
def get_num_tokens(self, model: str, credentials: dict, texts: List[str]) -> int:
    encoding = tiktoken.get_encoding("cl100k_base")
    return sum(len(encoding.encode(text)) for text in texts)   # ← 返回一个整数
```

而 Dify 插件 SDK 的基类契约（`dify_plugin/interfaces/model/text_embedding_model.py`）是：

```python
@abstractmethod
def get_num_tokens(self, model: str, credentials: dict, texts: list[str]) -> list[int]:
```

**必须返回 `list[int]`**（每个文本一个数字），官方插件也是这么写的：

```python
return [len(encoding.encode(text)) for text in texts]
```

返回整数 → daemon（Go）反序列化 `GetTextEmbeddingNumTokensResponse.num_tokens []int` 失败：

```
cannot unmarshal number into Go struct field
GetTextEmbeddingNumTokensResponse.num_tokens of type []int
```

**后果很严重**：`calculate_segment_token_counts()` 在索引流程里是**存分段之前**调用的
（`api/core/rag/index_processor/processor/paragraph_index_processor.py`），它一抛异常，
分段一个都存不下来 → 文档状态「错误」、0 分段、原始文件大小显示 `-`。
**不是嵌入失败，是根本没走到嵌入。**

### 2. `Decimal` 没导入（就算修好第 1 个也会炸）

同文件 51–53 行用了 `Decimal("0.0")`，但整个包**没有任何一处 `from decimal import Decimal`**：

```python
usage = EmbeddingUsage(
    tokens=...,
    unit_price=Decimal("0.0"),      # ← NameError
    price_unit=Decimal("0.0"),
    total_price=Decimal("0.0"),
    ...)
```

就算修好 bug 1，第一次真正发起 embedding 调用时会 `NameError: name 'Decimal' is not defined`。

**两个加起来 = 这个插件从来没有能跑通过。**

## 装完之后必须做的两件事

### 1. 重新索引文档

旧的文档停在「错误」状态、0 分段，不会自己好。
知识库 → 那份文档 → **重新索引**（或删掉重新上传）。

验证：**别再信「嵌入已完成」那句提示**，去文档里看**分段数不为 0**，
再到知识库左侧做一次 **召回测试**，问一句「发什么快递」，能召回片段才算通。

### 2. 把 embedding 模型从 Embedding-V1 换成 bge-large-zh

插件里两个模型的上下文上限不一样：

| 模型 | context_size | 向量维度 |
|---|---|---|
| Embedding-V1 | **384** tokens | 384 |
| bge-large-zh | **512** tokens | 1024 |

拿你这份 FAQ 实测（tiktoken cl100k_base 逐行数）：

- 最长的一行是第 27 行「衣服洗了成团了」= **413 tokens** → **超过 Embedding-V1 的 384**
- 其余 34 行都低于 384；最长 413、中位 88

也就是说 Embedding-V1 会**把最长那条问答的答案尾部丢掉**（那条答案本身就有 304 字）。
换成 bge-large-zh 全都装得下，而且中文检索质量明显更好（1024 维 vs 384 维）。
两个模型在这个插件里都是 0 价，没有理由不换。

> 如果 `bge-large-zh` 在星河社区那边调不通（插件把模型列出来了，但上游不一定真提供），
> 就退回 Embedding-V1，只是第 27 行那条会被截断。
